# 利润运营与独立上游渠道归属

利润运营页 `/admin/profit-operations` 按独立上游渠道实体聚合请求、收入与估算利润。渠道实体具有不可变内部 ID、唯一且创建后不变的 code、唯一可编辑名称和备注；账号使用独立 FK 显式归属。

账号归属不由 URL 派生。同一渠道可包含不同 URL、无效/未知 URL、动态 OAuth 或不支持读取 URL 的账号；不同渠道也可包含相同 URL。只有当前未绑定账号才按现有安全有效 URL 自动聚合，无法识别时保留 unknown。利润筛选与下钻使用实体内部 ID，不受 URL、名称和分页位置变化影响。

`/admin/upstream-channels` 管理实体与分页成员；账户管理支持创建时绑定、编辑、批量选择。一次绑定最多 100 个明确账号，页面展示受影响账号并要求确认，写入使用 revision CAS 后 GET 读回。修改渠道成员会递增渠道 revision，旧确认失效。

删除有成员的渠道一律冲突。管理员须先在成员页明确选中有界账号并确认解绑、重新读取版本后，才可删除空渠道。关联表外键禁止渠道级联删除；解绑只改变当前归属，不修改账号路由、历史 usage 或账本。软删除账号保留绑定与历史请求归属；真正物理删除时仅清除其绑定，migration 313 触发器推进原渠道 revision。归属报表是当前配置，不代表历史路由快照。

## 财务口径

用户请求估算成本 = 保存的 `usage_logs.total_cost` × 当前账号成本倍率 `extra.cost_multiplier`；未保存时沿用默认 0.1。内部请求成本来自 `internal_request_costs` 的请求时快照。合计成本 = 用户请求成本 + 测智成本 + 监控成本；估算利润 = 已保存的用户 `actual_cost` 合计 − 合计成本。账号计费倍率不再叠加；服务器等其他运营费用未纳入。

## 内部请求成本

迁移 339 新建独立内部成本账本，记录分组测智、账号定时测智、V1 分组/端点探测、V2 糖果检测和 V3 空闲补探的来源、账号/分组、请求模型/实际模型、token、标准成本、当时成本倍率、成本金额及完整性。它不写 `usage_logs`，也不调用余额或用户/API Key 配额扣减。每次重试按实际尝试的账号独立计量；最终失败不抹掉已产生的成本。一次尝试内各响应流分别计量，累计 SSE 用量不会重复累加。数据库写入使用稳定 ID 去重并重试一次；进程中止或持久化持续失败仍可能产生未记录开销，日志会记录写入失败。

利润页默认 `source=all`，可选 `user/internal/pelican/monitor`。用户请求数和延迟指标仍只来自真实用户；内部次数、测智成本、监控成本另列。只有内部开销而没有用户请求的账号也会进入列表。时间使用含起点、不含终点的请求开始时间；历史回填只能使用旧记录保存的完成/检查时间。账号、分组、模型、上游及显式渠道筛选应用于两类开销。内部请求的实际模型目前同时作为记录模型和上游模型口径。

使用记录新增管理员专属「内部请求」页签，提供独立时间、账号、分组、模型及来源筛选，显示请求当时的倍率和金额。观察员/用户视图不开放这些内部记录。

不完整用量保留已确认的部分金额，同时将合计成本、利润和毛利率标为未知，避免把缺失当作零。未关联实际调度账号的 V1 端点探测只保留能计量的标准金额，不使用配额查询的关联账号猜测采购成本；改用分组探测可以获得实际账号及其成本倍率。无账号归属的内部开销单独显示为 `unknown:unattributed_internal`，不分摊给其他上游。

迁移仅导入仍保留的分组测智结果、V3 补探成本、V1 和 V2 检测历史。旧的跨账号重试成本只有合计，不能全部归到最终账号，故保留为未归属开销。旧日志未保存 token 或倍率时留空，不乘当前倍率重算；已被清理的历史、仅剩日汇总且缺少可靠逐笔归属的成本，以及旧账号级测试未记录的成本无法恢复。导入的 V1/V2 无成本记录标为未知。账本无测试计划/账号删除级联，不随展示历史清理而消失。用户请求成本仍遵循当前配置重估，内部成本固定为快照，两者在页面明确说明。

标准收费基数与收入均按历史保存值展示，不按当前价卡重算。订阅计价不等于现金收入；未知 URL/动态路由不虚构归属。若缺少有效金额/倍率，汇总按既有逻辑显示未知。

Migration 312 创建 `upstream_channels` 与 `upstream_channel_bindings`；不按 URL、展示名称或历史 usage 猜测实体关系。早期分支中的 URL-key 备注表、API 和 UI 已从本 PR 删除，因此 URL 只用于未绑定账号的只读自动归类，不是可编辑渠道身份。

验收和变更记录见 [PROGRESS.md](../PROGRESS.md)。

## 大数据量查询

利润快照的服务端查询预算为 5 分钟，页面等待上限为 5 分 30 秒，独立于其他管理接口的默认超时。等待期间页面保持汇总状态；切换查询或离开页面仍会取消旧请求。反向代理的读取超时应至少为 330 秒，避免先于应用中断响应。

统计只投影计算所需的用量字段，保留完整时间范围、精确合计和延迟分位数。分页仍只限制展示条数，不截断统计样本。超出查询预算时接口返回 HTTP 504 和 `PROFIT_OPERATIONS_TIMEOUT`，页面明确显示统计超时，不将未完成结果显示为零。
