# V1 分组监控与使用记录缓存率

新建 V1 监控默认选择「站内分组」，选择启用的分组及主模型即可保存，不需要 URL 或 API Key。附加模型也可从该分组目录选择。外部 URL / API Key 与配额模式继续可用，旧监控保持原来的来源；编辑时可显式切换到站内分组。

分组探测复用鹈鹕与 V3 的调度器、账号凭据、模型映射、并发和故障切换，发送轻量算术问题并校验答案，不发布鹈鹕作品、不计入用户使用记录。只有系统启用 V1 时运行，探测会产生少量上游用量。分组删除或停用后报错，保留绑定，不自动退回外部凭据。

V1 和鹈鹕的模型下拉共用管理端只读接口 `/api/v1/admin/pelican-group-tests/models/:id`，从站内账号配置与分组路由读取，不向供应商发起请求。目录遵守模型映射、分组白名单及账号在分组中的模型限制；可调度性仍会在实际探测时重新判断。切换分组会清空模型选择，读取失败显示重试，编辑已有记录时保留原模型并标注当前不在目录中的项。

V1 管理列表与用户卡片显示绑定分组近 24 小时的缓存率。来源为该分组的真实 `usage_logs`，不是探测结果，也不是按请求平均：

`SUM(cache_read_tokens) / SUM(input_tokens + cache_read_tokens + cache_creation_tokens)`

与使用记录页面的缓存率采用相同的互斥输入 Token 口径，输出 Token 不计入分母。统计覆盖整个分组而非单个探测模型。没有使用记录、没有输入 Token、读取失败或外部监控没有分组绑定时显示「—」；有输入但没有缓存命中时显示 `0%`。

部署时需应用迁移 `338_channel_monitor_group_probe.sql`。新增可空 `group_id`，旧监控不变；保留已删除分组的编号是为了明确报错而非静默换源。

用户端缓存率固定采用与可用率并列的大数值样式，字号与红、黄、绿文字渐变均与可用率一致，无数据为灰色「—」。缓存率仍统计近 24 小时，不随可用率的 7/15/30 天窗口切换。
